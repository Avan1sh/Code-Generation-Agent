The measurement

The noise floor is wider than the effect

single_shot and the agent’s attempt 1 send an identical prompt to an identical model at temperature 0. They still disagreed on 3 of 30 problems. Provider-side batching makes temperature 0 non-deterministic, so that disagreement rate is the floor beneath which this harness cannot resolve anything.

Undirected resampling is the expensive strategy, and it scored lower. best_of_n costs 2.9× per solve because it always draws all three samples whether or not the first worked. The agent costs the same as the baseline — the loop only spends when it fails. That gap is far outside the noise floor.

What the two hard problems had in common

The obvious answer looks correct, is silently accepted, and silently does nothing. Asked to serialise a subclass through a base-typed field, the model wrote ConfigDict(serialize_as_any=True). That is not a ConfigDict key — but ConfigDict is a TypedDict, so it is accepted at runtime, stored, and has no effect. No error, no warning; the subclass field simply vanishes from the output.

Problems asking “which v2 name replaced this v1 name?” are a lookup this model performs reliably. Problems where a plausible construct misbehaves in silence are the ones with discriminating power.

Architecture

Five nodes, one bounded loop

test_gen ──▶ generate ──▶ static_check ──pass──▶ execute ──pass──▶ END
                 ▲              │                    │
                 │          fail│               fail │
                 │              ▼                    ▼
                 └────────── reflect ◀───────────────┘
                        (only while attempts remain)

Termination is proven, not asserted

Node-level guards compare attempt_number to max_attempts and write a terminal status; routers only read it. A test runs the graph with a stub model that never succeeds and checks the bound holds at 1, 2, and 3 attempts on both failure paths.

Generated code never touches exec()

Every solution runs under pytest in a subprocess with a wall-clock timeout, plus POSIX memory and CPU ceilings where available. The sandbox proves itself healthy on known-good code before the eval spends anything.

The eval set validates itself

All 40 problems ship a hand-written reference solution that must pass its own tests and clear the static gate. No prompt may leak a v2 API name — otherwise the eval would measure instruction-following, not knowledge.

Preflight before budget

Groq retired both Llama models mid-project. Two full runs recorded 90/90 errored rows and printed 0/30 for every method — which reads exactly like catastrophic model failure. A one-call preflight now aborts on a dead endpoint before anything is spent.

Raw counts, never bare percentages

Every rate ships with the counts behind it. At n = 30 one problem is 3.3 points, and the denominator is the most important part of the number.

Errors count as failures

A crashed row is recorded, never skipped — a dropped row silently shrinks the denominator and inflates every rate. The analyser refuses to print a summary when there is no data behind it.

Limitations

What these numbers cannot support

—  n = 30, noise floor ≈ 3 problems. Only differences larger than that are interpretable. The loop’s +1 is not.

—  Ceiling-limited. At 86.7% baseline there is little room to improve, so this run cannot strongly support or refute the hypothesis either way.

—  Single run per configuration. No seed variance, no repeated trials. Point estimates only.

—  Runs 1 and 2 are unreproducible. Both model IDs were retired by the provider.

—  POSIX sandbox limits are unverified on the machine this was built on. The tests exist and are skipped on Windows, so the memory and CPU ceilings remain a design claim rather than a measured one.

—  Pydantic v2 is close to exhausted as a discriminating domain at this model tier. That is a property of the eval, not a result about self-correction.
